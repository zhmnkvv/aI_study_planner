# AI Study Planner

Учебный эксперимент: создание простого веб-инструмента с помощью AI-ассистента и его пошаговое улучшение через уточняющие промпты.

Код инструмента: [`tools/study-planner/`](tools/study-planner/)

## 1. Описание инструмента

**AI Study Planner** — простой веб-инструмент для планирования учебного дня.

Пользователь вводит список задач на день (название, примерную продолжительность и приоритет) и указывает своё свободное время. Инструмент формирует последовательное расписание: сначала важные задачи, затем менее важные, с короткими перерывами после длительных задач.

**Какую проблему решает:** когда задач много, а времени ограничено, сложно быстро понять, в каком порядке их выполнять и что успеется за день. Инструмент показывает готовый план и сразу сообщает, какие задачи не поместились в свободное время.

### Как запустить

Инструмент не требует установки зависимостей и сборки.

- **Вариант 1:** открыть файл `tools/study-planner/index.html` в браузере.
- **Вариант 2:** запустить локальный сервер (нужен Python 3) и открыть http://127.0.0.1:8765:

  ```bash
  python -m http.server 8765 --directory tools/study-planner
  ```

  На Windows вместо `python` может понадобиться `py`.

### Структура

| Файл | Назначение |
|---|---|
| `index.html` | Разметка страницы: свободное время, форма задач, расписание |
| `planner.js` | Логика составления расписания (без привязки к интерфейсу) |
| `app.js` | Работа с интерфейсом: добавление/удаление задач, вывод плана |
| `style.css` | Простые стили |

## 3. Первая версия

Первая версия — минимальная рабочая страница на HTML, CSS и JavaScript без внешних зависимостей.

Что она умела:

- задавать начало и конец свободного времени;
- добавлять задачи с названием, продолжительностью (в часах) и приоритетом (высокий / средний / низкий);
- удалять задачи из списка;
- по кнопке «Сформировать расписание» выстраивать задачи друг за другом, начиная с начала свободного времени;
- показывать, сколько свободного времени осталось и какие задачи не поместились;
- сообщать об ошибке, если конец свободного времени раньше начала.

Ограничения первой версии:

- задачи сортировались по приоритету, но если важная задача не помещалась целиком, она просто пропускалась, а её время занимали менее важные задачи;
- задачи шли вплотную друг к другу, без перерывов.

## 4. Улучшение №1

Первое улучшение — **корректный учёт приоритетов задач**.

### Что не так

Инструмент формировал расписание, но недостаточно хорошо учитывал приоритет задач: важные задачи могли оказаться после менее важных или не попасть в план вовсе.

При проверке выяснилось, что при достаточном количестве времени задачи уже шли в порядке «высокий → средний → низкий». Проблема проявлялась, когда времени не хватало: если задача с высоким приоритетом не помещалась целиком, она пропускалась, а освободившееся время отдавалось задачам с более низким приоритетом.

Пример: свободное время 10:00–13:00, задачи «NLP» (высокий, 4 ч), «Спорт» (средний, 1 ч), «Чтение» (низкий, 0,5 ч). В расписание попадали «Спорт» и «Чтение», а «NLP» — нет.

### Как должно быть

При формировании расписания сначала планируются задачи с высоким приоритетом, затем со средним, затем с низким. При этом учитываются продолжительность каждой задачи и доступное пользователю время.

### Зачем

Пользователь должен в первую очередь видеть и выполнять наиболее важные задачи — особенно если свободного времени недостаточно для выполнения всех задач.

### Что изменилось

- Если задача не помещается целиком, ей отдаётся всё оставшееся время, и в расписании она отмечается как «частично — не хватило времени».
- Все менее приоритетные задачи после этого попадают в список «Не поместились».
- Время больше никогда не уходит на менее важные задачи, пока более важная не запланирована.
- Изменённые файлы: `planner.js` (логика цикла в `buildSchedule`), `app.js` (пометка «частично»).

Тот же пример после улучшения: `10:00–13:00 NLP (частично)`, «Спорт» и «Чтение» — в списке «Не поместились».

## 5. Улучшение №2

Второе улучшение — **реалистичные перерывы между длительными задачами**.

### Что не так

Расписание могло получаться слишком плотным: несколько продолжительных задач шли подряд без перерыва, например 10:00–12:00, 12:00–13:30, 13:30–15:30.

### Как должно быть

Между длительными задачами добавляются короткие перерывы: если задача занимает 60 минут или больше, после неё предусматривается перерыв около 10–15 минут — если свободное время это позволяет.

### Зачем

План должен быть не только логически правильным, но и реалистичным для человека. Пользователь должен иметь возможность следовать расписанию без непрерывной работы несколько часов подряд.

### Что изменилось

- После задачи длительностью 60 минут и больше перед следующей задачей ставится перерыв 15 минут.
- Перерыв добавляется, только если следующая задача после него всё ещё помещается целиком. Поэтому перерывы не выходят за пределы свободного времени и не вытесняют задачи из плана.
- После последней задачи и после коротких задач перерыв не ставится.
- Система приоритетов из улучшения №1 сохранена.
- В расписании перерыв отображается отдельной серой строкой «☕ Перерыв».
- Изменённые файлы: `planner.js` (константы `LONG_TASK_MINUTES`, `BREAK_MINUTES` и вставка перерывов), `app.js` (вывод перерыва), `style.css` (стиль строки перерыва).

Пример из ТЗ после улучшения (10:00–22:00):

| Время | Задача |
|---|---|
| 10:00 – 12:00 | Подготовиться к NLP (высокий) |
| 12:00 – 12:15 | Перерыв |
| 12:15 – 13:45 | Сделать GitHub homework (высокий) |
| 13:45 – 14:00 | Перерыв |
| 14:00 – 16:00 | Поработать над проектом (средний) |
| 16:00 – 16:15 | Перерыв |
| 16:15 – 17:15 | Спорт (средний) |

## 6. Тестирование

Инструмент тестировался вручную в браузере после каждого этапа:

- **Первая версия:** добавление и удаление задач, построение расписания на примере из ТЗ, случай, когда задачи не помещаются в короткое окно, и ошибка при неверном времени (конец раньше начала).
- **Улучшение №1:** задачи разных приоритетов в разном порядке добавления; нехватка времени для задачи с высоким приоритетом; окно, в которое задачи помещаются ровно.
- **Улучшение №2:** несколько длинных задач подряд; окна, где на перерыв хватает или не хватает места; только короткие задачи (без перерывов); проверка, что расписание не выходит за конец свободного времени.

### Что мешает при использовании

1. **Нельзя отредактировать добавленную задачу.** Если допущена ошибка в названии, продолжительности или приоритете, задачу приходится удалять и добавлять заново.

2. **Перерывы нельзя настроить или отключить.** Перерывы добавляются автоматически (сейчас — 15 минут после длительной задачи), но пользователь не может изменить их продолжительность или отказаться от них.

3. **Нет подсказки, как использовать оставшееся время.** Если часть свободного времени остаётся незаполненной, инструмент просто показывает, сколько его осталось. Было бы полезно подсказать пользователю, что с ним сделать — например, предложить добавить ещё одну задачу или оставить это время свободным.

4. **Длинное расписание неудобно просматривать.** При большом количестве задач расписание становится длинным; в дальнейшем можно улучшить визуальное отображение, чтобы план было удобнее быстро просматривать.
